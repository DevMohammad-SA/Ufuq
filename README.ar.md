# أُفق — رحّال

اقرأ هذا الملف بالإنجليزية: [README.md](README.md)

منصة إدارة **برنامج أُفق التنموي** (برنامج قيمي مهاري لمدة 14 أسبوعًا) التابع
لـ**جمعية صقيل لتنمية الشباب**. يسجّل المشرفون الحضور اليومي والأسبوعي
ويراجعون مهمة أسبوعية، ويكسب المشاركون عملة مكافآت ثلاثية ويتقدّمون نحو
الترشح لـ"رحلة النخبة". المنتج الموجَّه للمستخدم النهائي يحمل هوية **رحّال**
— اسم النطاق الداخلي "أُفق" وميزات داخلية مثل الحلقة القرآنية باقيان في أسماء
الكود والموديلات، لكن أُزيلا من النصوص المواجهة للمشارك.

كامل الواجهة ولغة المجال **عربية** (`ar-sa`، `Asia/Riyadh`، اتجاه من اليمين
لليسار). النسخة الإنجليزية في [`README.md`](README.md). التوثيق التقني
التفصيلي في مجلد [`docs/`](docs/)، وسجل الإصدارات في
[`CHANGELOG.md`](CHANGELOG.md).

**آخر إصدار موسوم: 1.2** (راجع [`CHANGELOG.md`](CHANGELOG.md)). أبرز ما فيه:
عدة مهام أسبوعية مفتوحة بالتوازي بصيغ تسليم حرة بمنطق AND/OR
([`docs/weekly-tasks.md`](docs/weekly-tasks.md))، واستبدال شريط التنقل الأفقي
بقائمة جانبية قابلة للطي ودرج جوال
([`docs/navigation.md`](docs/navigation.md)). يحوي المستودع أيضًا تحديثات بعد
1.2 **غير موسومة** موثقة تحت `Unreleased`؛ لا يعني ذلك إصدار رقم جديد.

## نظرة عامة

- كل مشارك ينتمي إلى **بيئة** (`Group`)، ويمكن إسناد **مشرف بيئة واحد أو
  أكثر** لها (`Group.supervisor` أصبح حقل علاقة متعدد-لمتعدد).
- مع تسجيل المشرفين للحضور ومراجعة المهام، يكسب المشارك عملة ثلاثية، تُحوَّل
  كلها معًا عبر دالة واحدة `apply_points_delta` (`participants/views.py`):

  | العملة | الحقل | القاعدة |
  |--------|------|---------|
  | النقاط | `points` | عملة الترتيب. **قابلة للتصفير** على مستوى البرنامج (تُحفظ لقطة أولًا). لم تعد تُعرض كبطاقة مستقلة في لوحة المشارك، لكنها لا تزال محسوبة ومستخدَمة في ترتيب مؤشر رحلة النخبة. |
  | الأميال | `miles` | `دلتا النقاط × 10`، تُطبَّق معًا. **لا تُصفَّر أبدًا**. |
  | النقاط الشرائية | `purchase_points` | تُصرف في المتجر. **لا يمسّها إجراء التصفير**؛ المتجر هو الميزة الوحيدة التي تعدّلها مباشرة، متجاوزًا `apply_points_delta`. |

  كل رصيد محدود بحد أدنى صفر.

- **مصادر النقاط** (قيَم مأخوذة حرفيًا من `participants/views.py`):

  | المصدر | النقاط | ملاحظة |
  |--------|--------|--------|
  | اللقاء الأسبوعي | 8 حضور + 2 حضور مبكر (مستقلان) | `MeetingAttendance` — علم الحضور المبكر يمنح نقطتين وحده حتى بلا تعليم الحضور |
  | الحلقة القرآنية | 3 حضور + 2 إنجاز (مستقلان) | `CircleAttendance` |
  | فعالية الأسبوع | 10 (كاملة، علم حضور واحد) | `WeeklyActivityAttendance` — جديدة |
  | قبول المهمة الأسبوعية | 10، أو 12 إن كانت "مميزة" (⭐) | `TaskSubmission.is_featured` |
  | نقاط إضافية / خصم يدوي | من -1000 إلى +1000، بسبب إلزامي | `ExtraPointsView`، للمشرف العام/النظام فقط — جديد |

  كل واحدة من هذه (باستثناء المتجر) تكتب أيضًا صفًا في سجل تدقيق
  `PointsLedgerEntry`، يُعرض لكل بيئة أو على مستوى البرنامج في **سجل النقاط**
  الجديد (`participants:points_ledger`) مع تاريخ تسجيل وتاريخ حدث منفصلين.
  لوحة المشارك تعرض فقط «النقاط المضافة لك»: أحدث 50 حركة موجبة، لا سجلًا
  كاملًا ولا خصومات أو حركات صفرية. التفاصيل الكاملة:
  [`docs/points-system.md`](docs/points-system.md).

## الأدوار الأربعة

معرّفة في `accounts/models.py` (`Role`):

| الدور | القيمة | ملخص |
|------|--------|------|
| مشارك | `participant` | يدخل بـ **رقم الهوية + كلمة المرور**. لوحة شخصية (فيها سجل نقاط مدمج ومؤشر رحلة النخبة)، صفحة تسليم تعرض **كل المهام المفتوحة**، المتجر. |
| مشرف بيئة | `group_supervisor` | يسجّل الحضور ويستعرض البيانات والتقرير وتسليمات المهام وطلبات المتجر في **كل بيئاته المسندة**. مراجعة التسليمات اطلاع فقط حتى يمنحه المشرف العام تفويضًا صريحًا. |
| مشرف عام | `general_supervisor` | على مستوى البرنامج: استيراد إكسل، استمارة إضافة مشارك مفرد، إدارة المهام وتعديلها، إدارة المتجر، منح نقاط إضافية، تصفير النقاط، سجل النقاط الكامل، كل البيئات، ومنح/سحب تفويض مراجعة المهام، وإدارة بيانات المشاركين وحسابات المشرفين من واجهة رحّال. |
| مشرف النظام | `superadmin` | إدارة على مستوى البرنامج وأدمن Django (`is_staff`/`is_superuser`)؛ يصل أيضًا إلى واجهة إدارة الحسابات، لكنه لا يدير تفويض مشرف البيئة لمراجعة المهام ولا يرى ملاحظات اللقاء الخاصة. |

المصفوفة الكاملة للصلاحيات:
[`docs/roles-and-permissions.md`](docs/roles-and-permissions.md).

## الميزات الحالية

كل بند أدناه له View ومسار حقيقي — راجع [`docs/features.md`](docs/features.md)
لتفصيل الـ View والقالب لكل واحد.

- **ثلاثة أنواع تحضير مستقلة تمنح نقاطًا**، كلها بنمط كشف جماعي + منتقي تاريخ: اللقاء
  الأسبوعي (مشرف البيئة، بيئته فقط)، الحلقة القرآنية (حضور وإنجاز يُحتسبان
  منفصلين)، وفعالية الأسبوع. إعادة إرسال الكشف تطبّق **الفرق فقط**، فلا
  تتضاعف النقاط. لا تعرض القوالب نجاح الحفظ إلا بعد اكتمال المعاملة الذرية، مع
  التاريخ المختار في الكشف نفسه.
- **تحضير رحلة النخبة**: كشف مستقل لمشرف البيئة لطلابه في بيئاته المسندة، بأربع
  حالات متبادلة: حاضر، معتذر، غائب، وغير مرشح. يحفظ البيانات وإحصاء كل حالة
  فقط؛ لا يمنح أو يخصم نقاطًا أو أميالًا أو نقاطًا شرائية، ولا يكتب في سجل
  النقاط أو يغيّر مؤشر رحلة النخبة.
- **المهام الأسبوعية**: عدة مهام مفتوحة بالتوازي، وكل مهمة تُنشأ **غير نشطة**
  ولا تظهر حتى يفعّلها المشرف، ثم تختفي وحدها عند موعد التسليم. صيغ التسليم
  خانات اختيار حرة (PDF / صورة / صوت / فيديو / نص مباشر) تُجمع بمنطق
  **AND** ("قدّمها كلها معًا") أو **OR** ("اختر واحدة")، والتحقق كله خادمي.
  المراجعة قبول (+10، أو +12 إن كانت "مميزة ⭐") أو رفض بسبب يراه الطالب أو
  إعادة للتعديل بملاحظة إلزامية ودون نقاط. الإعادة لا تمدد الموعد؛ يستطيع الطالب
  تعديل السجل نفسه وإرساله قبل الموعد الأصلي فقط، بينما إعادة الفتح الإدارية هي
  الاستثناء الصريح بعده. يعدّل المشرف العام/النظام المهمة القائمة (الاسم والوصف
  والموعد والصيغ) من دون إنشاء نسخة أو تغيير التسليمات السابقة.
- **المتجر**: الطالب يصرف نقاطه الشرائية، والمشرف يضيف/يعدّل/يحذف المنتجات
  ويكمل الطلبات أو يسترجعها. المخزون والرصيد يُعاد فحصهما تحت
  `select_for_update()` داخل معاملة.
- **سجل النقاط** (`PointsLedgerEntry`): صف تدقيق لكل حركة نقاط، ببحث وفرز
  وتصفية — مشرف البيئة يرى بيئته، والمشرف العام يرى البرنامج كله.
- **تصفير النقاط مع لقطة تاريخية**: يصفّر `points` وحدها بعد حفظ رصيد كل
  مشارك في `PointsResetSnapshot` داخل نفس المعاملة، وأحداث التصفير السابقة
  قابلة للاستعراض.
- **جدول بيانات المشاركين** مع بحث وفرز وتصفية، و**تصدير PDF** بالترويسة
  الرسمية (WeasyPrint وخط Tajawal مضمَّن).
- **تقرير الطلاب وملف الطالب التفصيلي**: عرض إشرافي للقراءة فقط مع فلاتر تاريخ
  وترقيم مستقل للسجلات، مقيد بكل بيئات مشرف البيئة المسندة. لا يعيدان إنشاء
  طلب متجر محذوف أو محاولات تسليم استُبدلت/حُذفت.
- **تفويض مراجعة المهام**: المشرف العام يمنح أو يسحب قبول/رفض تسليمات مشرف
  البيئة ضمن نطاقه الحالي فقط؛ الخادم يعيد فحص التفويض عند كل POST.
- **الحسابات**: استيراد إكسل أو استمارة مشارك مفرد؛ كلمة المرور الأولى هي رقم
  الهوية مع `must_set_password` يفرض تغييرها عند أول دخول؛ واسترجاع كلمة
  المرور بموافقة المشرف العام.
- **إدارة المشاركين والمشرفين**: المشرف العام ومشرف النظام يعدّلان البيانات
  الأساسية للمشارك من صفحة منفصلة، ويديران مشرفي البيئة/العموم من واجهة رحّال
  (إضافة وتعديل وتعطيل ناعم مؤكد) من دون منح المشرف العام صلاحيات أدمن Django.
  ويمكنهما تعطيل حساب مشارك نشط أو استعادته بعد تأكيد؛ لا يحذف ذلك المستخدم أو
  بياناته، ولا تعيد الاستعادة أي رصيد أو سجل. التفاصيل:
  [`docs/features.md`](docs/features.md) و[`docs/roles-and-permissions.md`](docs/roles-and-permissions.md).
- **التنقل**: قائمة جانبية قابلة للطي على سطح المكتب (حالتها محفوظة في
  `localStorage`)، وشريط سفلي ثابت + درج منزلق على الجوال، مع شارات إشعارات
  حيّة — [`docs/navigation.md`](docs/navigation.md).
- **لوحة الأدمن** على `/admin/` بثيم django-unfold بألوان رحّال ومصحّحة
  الاتجاه.

  (`USE_POSTGRES=True`). راجع [الرفع والتحديث](#الرفع-والتحديث).

## التشغيل المحلي للتطوير

```bash
# 1. تثبيت الاعتماديات في بيئة معزولة مُدارة
uv sync

# 2. إعداد متغيرات البيئة
cp .env.example .env
#    عدّل .env — SECRET_KEY مطلوب؛ DEBUG افتراضيًا False

# 3. تطبيق الهجرات
uv run python manage.py migrate

# 4. إنشاء حساب إداري (يُضبط الدور superadmin تلقائيًا)
uv run python manage.py createsuperuser

# 5. تشغيل خادم التطوير
uv run python manage.py runserver
```

- التطبيق: <http://127.0.0.1:8000/>
- الأدمن: <http://127.0.0.1:8000/admin/>

### متغيرات البيئة

التطوير المحلي يحتاج المتغيرَين الأولين فقط؛ البقية تخص إعداد Docker
الإنتاجي (`.env.docker`، راجع [الرفع والتحديث](#الرفع-والتحديث)).

| المتغير | مطلوب؟ | الافتراضي | الوصف |
|--------|--------|-----------|-------|
| `SECRET_KEY` | نعم | — | مفتاح Django السري |
| `DEBUG` | لا | `False` | وضع التصحيح |
| `ALLOWED_HOSTS` | لا (إنتاج: نعم) | `[]` | قائمة نطاقات مفصولة بفواصل |
| `CSRF_TRUSTED_ORIGINS` | لا (إنتاج: نعم) | `[]` | نطاقات HTTPS موثوقة مفصولة بفواصل |
| `USE_POSTGRES` | لا | `False` | `True` يبدّل `DATABASES` إلى PostgreSQL |
| `DB_ENGINE` | لا (إنتاج: مع `USE_POSTGRES`) | `django.db.backends.postgresql` | محرّك قاعدة البيانات |
| `DB_NAME` / `DB_USER` / `DB_PASSWORD` / `DB_HOST` | مع `USE_POSTGRES` | — | معطيات اتصال PostgreSQL |
| `DB_PORT` | لا | `5432` | منفذ PostgreSQL |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | مع خدمة `db` في Docker | — | يقرأها تصوير `postgres` الرسمي نفسه عند أول تشغيل؛ يجب أن تطابق `DB_NAME`/`DB_USER`/`DB_PASSWORD` تمامًا (نفس القيَم بأسماء متغيرات مختلفة — تكرار يفرضه تصميم تلك الصورة نفسها). |

الملفات `.env`، `.env.docker`، `db.sqlite3`، و`media/` مستثناة من Git.

### أوامر شائعة

```bash
uv run python manage.py makemigrations
uv run python manage.py migrate
uv run python manage.py check
# مجموعة SQLite سريعة ومعزولة (قاعدة وmedia في الذاكرة)
SECRET_KEY='<local-only>' USE_POSTGRES=False uv run python manage.py test --settings=config.test_settings --noinput
# تكافؤ PostgreSQL بعد تهيئة قاعدة محلية مؤقتة عبر Unix socket
SECRET_KEY='<local-only>' uv run python manage.py test --settings=config.test_postgres_settings --noinput
```

يستخدم `config.test_settings` قاعدة SQLite في الذاكرة و`InMemoryStorage`
وMD5 لكلمات المرور لسرعة العزل. أما `config.test_postgres_settings` فلا يقبل
إلا Unix socket المحلي `/var/run/postgresql` (ويمكن ضبط
`UFUQ_TEST_DB_NAME` و`UFUQ_TEST_DB_USER`)؛ لا توجّهه إلى خادم بعيد أو قاعدة
إنتاج. شغّل الأوامر أعلاه لإصدار نتيجة للنسخة التي تختبرها.

> **ملاحظة WeasyPrint:** نقطة تصدير PDF
> (`/participants/data/export-pdf/`) تحتاج مكتبات النظام التي يعتمد عليها
> WeasyPrint (‏Pango، Cairo، GObject). هذه المكتبات **مثبَّتة داخل صورة
> Docker الإنتاجية** (`Dockerfile`)، فتصدير PDF يعمل هناك؛ جهاز تطوير محلي
> بلا هذه المكتبات ستتعطل فيه هذه النقطة فقط (الاستيراد كسول داخل الـ View
> فبقية الموقع لا تتأثر). ملف `static/images/letterhead.png` (الترويسة
> الرسمية المستخدمة كخلفية صفحات الـ PDF) **موجود في المستودع**. راجع
> [`docs/known-limitations.md`](docs/known-limitations.md).

## الرفع والتحديث

يحوي المستودع الآن إعداد نشر إنتاجي كامل عبر Docker:

| الملف | الدور |
|-------|-------|
| `Dockerfile` | يعتمد `python:3.12-slim`، يثبّت مكتبات النظام التي تحتاجها WeasyPrint وpsycopg2، ويثبّت الاعتماديات عبر `uv sync --frozen --no-dev`. |
| `docker-compose.yml` | أربع خدمات: `db` (PostgreSQL 16)، `web` (عبر Gunicorn)، `nginx` (بروكسي عكسي + تقديم static/media)، `certbot` (تجديد شهادات Let's Encrypt كل 12 ساعة). |
| `docker/entrypoint.sh` | ينتظر جاهزية PostgreSQL، يُشغّل `migrate` ثم `collectstatic`، ثم يُشغّل Gunicorn (3 عمّال، مهلة 120 ثانية). |
| `docker/nginx/nginx.conf` | إعداد HTTP فقط (Bootstrap) — يُستخدم قبل صدور أول شهادة TLS (يخدم تحدي ACME عبر HTTP-01). |
| `docker/nginx/nginx-ssl.conf` | إعداد HTTPS الكامل — يُفعَّل يدويًا بعد صدور أول شهادة. |
| `docker/certbot-init.sh` | سكربت تشغيل يدوي لمرة واحدة لإصدار أول شهادة Let's Encrypt. |
| `.env.docker.example` | قالب متغيرات بيئة الإنتاج — انسخه إلى `.env.docker` واملأ القيَم الحقيقية قبل `docker compose up`. |

```bash
cp .env.docker.example .env.docker
#    عدّل .env.docker بقيَم حقيقية: SECRET_KEY، ALLOWED_HOSTS، معطيات قاعدة البيانات...
docker compose up -d --build
#    أول مرة فقط، بعد أن تصبح المكدّسة متاحة عبر HTTP العادي:
./docker/certbot-init.sh
#    ثم فعّل HTTPS:
cp docker/nginx/nginx-ssl.conf docker/nginx/nginx.conf
docker compose up -d --force-recreate nginx
```

ملاحظات:
- ينتهي TLS عند Nginx؛ Gunicorn يرى HTTP عادي فقط عبر الشبكة الداخلية
  لـ Docker. `SECURE_PROXY_SSL_HEADER` في `config/settings.py` يثق بترويسة
  `X-Forwarded-Proto` القادمة من Nginx كي لا يرفض تحقق CSRF في Django طلبات
  POST عبر HTTPS.
- تجديد الشهادة تلقائي، لكن **Nginx لا يُعاد تحميله تلقائيًا بعد التجديد** —
  راجع [`docs/known-limitations.md`](docs/known-limitations.md).
- الدليلان المشار إليهما سابقًا بـ `دليل_رفع_الاستضافة.md` و
  `دليل_تحديث_الموقع.md` لا يزالان **غير مُتتبَّعين في هذا المستودع**؛ إن كانا
  موجودين لدى صاحب المشروع خارجيًا، يُستحسن إضافتهما إلى `docs/` ليصبحا
  مرجعًا فعليًا.
- **CI/CD:** يعمل `.github/workflows/deploy-production.yml` عند الدفع إلى
  `master` أو التشغيل اليدوي، ثم يستدعي عبر SSH
  `/home/mohammad/scripts/deploy-ufuq.sh`. السكربت خارج المستودع؛ أظهر سجل نشر
  تمت مراجعته نسخًا لقاعدة البيانات و`media/`، لكن ذلك ليس ضمانًا لسلوكه غير
  المرئي في كل تشغيل.

التفصيل التقني الكامل: [`docs/architecture.md`](docs/architecture.md#النشر-الإنتاجي-docker).

## بنية المشروع

```
config/         حزمة مشروع Django (الإعدادات، المسارات، wsgi/asgi)
accounts/       الهوية والمصادقة — User مخصص، Role، backend الدخول، middleware
participants/   البيانات البرنامجية — Group، Participant، الحضور (ثلاثة أنواع)، المهام، المتجر، سجل النقاط، اللوحات
templates/      قوالب مشتركة (صفحة الهبوط العامة، وتجاوزات قوالب أدمن Unfold)
static/         الشعار، ترويسة PDF، خط Tajawal، ملف CSS لتصحيح اتجاه الأدمن، وقالب استيراد الإكسل
locale/         كتالوج الترجمة العربية لنصوص django-unfold وحدها
docker/         النشر الإنتاجي: سكربت التشغيل، إعدادات Nginx، سكربت تهيئة الشهادة
docs/           التوثيق التقني التفصيلي (بالعربية)
```

اتجاه الاعتماد دائمًا `participants → accounts` ولا عكس.
