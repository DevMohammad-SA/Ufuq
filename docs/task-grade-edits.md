# تعديل تقييم المهام والتميز اللاحق

## الإذن المستقل — 24 نوفمبر2026

من «إدارة المشرفين» يفتح المشرف العام «صلاحيات الطلاب والتقارير والتقييم» للمشرف المستهدف، ثم يحدد «تعديل تقييم المهام وإضافة أو إزالة التميز» ويؤكد الحفظ. هذا إذن مستقل لا يغيّر دور الهدف أو بيئاته أو حساب المانح، ولا يمنح تقارير أو متجرًا أو إدارة مهام. أهداف الصفحة هم مشرفو البيئة والمشرفون المحدودون والعامون الآخرون وفق حراسها الحالية؛ ليست للذات أو النظام أو `is_superuser` أو حساب مرتبط بملف طالب. الحساب المعطل للسحب فقط.

`SupervisorTaskGradePermission` سياسة OneToOne مستقلة بعلم `enabled` ومَن حدّثها ووقت التحديث. عدم وجودها يحفظ السلوك السابق: العام النشط فقط يملك التعديل. وجود `False` منع صريح حتى لو كان الهدف مشرفًا عامًا. البيئة والمحدود يحتاجان `True` صريحًا **و** إذن التصحيح التشغيلي الموجود: تفويض تصحيح البيئة أو `follow_tasks` للمحدود. المتابعة أو التقارير وحدها لا تمنح تعديلًا نهائيًا أو تميزًا لاحقًا. مشرف البيئة يعمل في بيئاته المسندة حاليًا فقط، والمحدود المخول في نطاق متابعة مهامه القائم. النظام لا يحصل على التعديل افتراضيًا أو بسبب صلاحية إعداد التقارير.

المنح والسحب بعد POST وCSRF وتأكيد واحد وقيم مربعات اختيار `yes` صارمة، وتحت أقفال حسابي المانح والهدف قبل السياسة. يحمل النموذج الجديد علامة وجود حقول التقييم؛ نماذج الصلاحيات المفتوحة قبل التحديث لا تغير السياسة الجديدة ضمنيًا. تعطيل المشرف أو تغيير دوره يسحب المنح الإيجابية إلى False ويحفظ سجلات المنع؛ لا تعيد إعادة التفعيل المنحة. سحب إذن التصحيح الأساسي يجعل إذن التعديل غير فعال أيضًا. الهجرة0030 تضيف الجدول فقط، دون سياسات جماعية أو تغيير أدوار أو أرصدة.

## التعديل المباشر

في تسليم مقبول أو متميز أو مرفوض أو معاد للتعديل، يظهر «تعديل التقييم» في القائمة وداخل معاينة العمل لمن يملك الإذن. يختار المراجع قبولًا أو متميزًا أو رفضًا، ويكتب سببًا مطلوبًا حتى2000 حرف، ثم يحفظ مباشرة. لا يلغى التقييم أولًا ولا يعود التسليم إلى قيد المراجعة في خطوة وسيطة. الرفض الجديد يظهر سببه للطالب؛ سياق المراجعة السابقة محفوظ في التدقيق قبل استبداله. حالة الرفض أو القبول النهائية تنهي الإعادة العادية للطالب، ولا تغير علامة إعادة الفتح الإدارية المستقلة أو الموعد أو الملف أو النص أو تاريخ التسليم.

المنحة الجديدة0/10/12، والعملية تطبق `new_award - old_award` فقط. قيمة قديمة `award_value=NULL` مع علامة منح True/NULL تحتاج تأكيدًا صريحًا0/10/12 بعد التحقق من الصرف الفعلي؛ لا تخمين من الحالة أو التميز أو عنوان حركة قديمة. False بلا قيمة محتسبة تعني0. التسليم المعلق يستخدم أدوات المراجعة الأولية القائمة، لا نموذج التصحيح النهائي.

## إضافة أو إزالة التميز بعد القبول

للتسليم المقبول يظهر زر «إضافة التميز» أو «إزالة التميز»، في القائمة والمعاينة، دون تعبئة نموذج التقييم الكامل. الطلب `set_featured` يحدد الحالة المطلوبة `is_featured=yes/no`، وليس تبديلًا أعمى. يبقى التسليم مقبولًا وتحفظ ملاحظاته وعمله وموعده وإعادة فتحه الإدارية، ويسجل وقت ومشرف آخر مراجعة والتدقيق.

| المنحة السابقة والجديدة | فرق النقاط | فرق الأميال | فرق النقاط الشرائية |
|---|---:|---:|---:|
| قبول10 ← متميز12 | +2 | +20 | +2 |
| متميز12 ← قبول10 | −2 | −20 | −2 |
| قرار مطابق لمنحة مؤكدة | 0 | 0 | 0 |

تظل الأرصدة محدودة بالصفر كما كانت؛ إزالة التميز لا تعيد شراءً سابقًا أو رصيدًا تاريخيًا. لا يمنح الزر نقاط القبول10 مرة ثانية. المنحة المجهولة تحتاج اختيار10/12 مؤكدًا قبل الإرسال. منحة0 أو غير صالحة تحتاج تعديل التقييم الكامل أولًا لتأكيد القبول ومنحته، ولا تتلقى منحة قبول جديدة من زر التميز. المعلق والمرفوض والمعاد لا يقبلون إجراء التميز المستقل.

## النسخ والأقفال والتدقيق

العمليات الثلاث — التعديل والتميز والإلغاء القديم — تمر بالإذن نفسه وتقرأ الدور والنشاط والسياسة من جديد. تحت معاملة تقفل حساب المشرف بـNO KEY UPDATE، ثم التسليم فقط عبر `select_for_update(of=("self",))` في نطاقه، ثم المشارك. يعاد التحقق من النطاق بعد انتظار قفل المشارك؛ انتقال الطالب لبيئة أخرى لا يسمح لصفحة مشرف بيئته السابقة بكتابة قرار عليه.

الطلب يحمل `review_version` مطابقًا لوقت المراجعة الكامل، وتغيره مراجعة جديدة؛ النسخة القديمة لا تستبدلها ولا تكرر فرق المنحة. المعرفات خارج BigAutoField والنسخ غير الصالحة والقيم المفردة المكررة ترفض دون كتابة. القرار المطابق لمنحة مؤكدة لا يكتب تدقيقًا أو حركة نقاط مكررة. يكتب التغيير `TaskGradeRevision`، وأي فرق غير صفري يمر حصريًا عبر `apply_points_delta` بمصدر WEEKLY_TASK، بتاريخ حدث التسليم الأول ووقت تسجيل التغيير الفعلي. لا حذف لتاريخ أو تعديل للقطات أو النقاط من هجرة الإذن.

المعاينة تنسخ نماذج القائمة المصرح بها وCSRF ومعرف التسليم والنسخة والاختيارات الحالية، بمعرفات حقول منفصلة. التميز عند القبول الأول يبقى مربعًا لا يقبل المهمة إلا عند الضغط على «قبول». أزرار التميز اللاحق ترسل POST أصليًا إلى الخادم؛ لا رسالة نجاح تخمينية أو تعديل بصري للرصيد قبل إقرار الحفظ. الحفظ المباشر يعرض نتيجة الخادم ويحافظ على فلتر المهمة والحالة.

`cancel_grade` ما زال موجودًا لحماية توافق الصفحات القديمة، لكنه لم يعد أداة الواجهة الحالية. يلزمه الإذن المستقل والنطاق والنسخة والتأكيد كما قبل؛ يسحب المنحة المؤكدة ويعيد PENDING وفق عقده القديم، ولا يمثل خطوة لازمة للتعديل الجديد.

## ملفات التنفيذ

`participants/capabilities.py` للإذن والسحب، و`supervisor_permissions.py` و`supervisor_permission_forms.py` لصفحة منح الصلاحيات، و`task_grading.py` لخدمات التقييم. الربط داخل `WeeklyTaskReviewView`، وقالب `weekly_task_review.html` وأصول `task-review-preview.js/css` للقائمة والمعاينة. الاختبارات ببيانات مصطنعة SQLite وPostgreSQL محلي، والنشر عبر مسار GitHubActions الموجود. راجع [دورة المهام](weekly-tasks.md) و[النقاط](points-system.md) و[الأدوار](roles-and-permissions.md).
