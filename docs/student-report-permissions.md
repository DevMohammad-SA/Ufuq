# صلاحيات إدارة الطلاب والتقارير

## منح الصلاحية دون تغيير الدور

من «إدارة المشرفين» يفتح المشرف العام النشط «صلاحيات الطلاب والتقارير» لمشرف بيئة أو مشرف محدود أو مشرف عام آخر. الحساب الذاتي ومشرف النظام و`is_superuser` والحساب المرتبط بملف طالب ليست أهدافًا. تقبل الصفحة العلامة الإدارية القديمة `is_staff` دون تغييرها أو تغيير كلمة المرور أو مجموعات وصلاحيات Django.

تحفظ الصفحة ثلاثة اختيارات مستقلة بعد `POST confirm=yes` واحد وCSRF: إدارة الطلاب، والاطلاع على التقارير، وإعداد وتصدير التقارير. لا تغيير بمجرد فتح الصفحة. لا يتغير دور المشرف أو إسناد بيئاته أو صلاحيات المانح. حساب المشرف العام يملك إدارة الطلاب بدوره أصلًا؛ خيارات التقارير تسمح بمنع تقاريره صراحةً دون إلغاء دوره أو إدارة الحسابات.

صفحة «صلاحيات محددة» القديمة ما زالت مختلفة: تحول مشرف البيئة إلى مشرف محدود وتزيل إسناد بيئاته بعد التأكيد، وتضبط المتجر والمهام والطلاب. لمنح إدارة الطلاب مع بقاء الدور والبيئات استخدم الصفحة الجديدة. لا تمنح خيارات المتجر أو المهام حقًا في التقارير تلقائيًا.

## إدارة الطلاب

`SupervisorCapability.manage_students` علم افتراضيهFalse. العام والنظام يحتفظان بالإدارة الأصلية؛ البيئة والمحدود يحتاجان علمًا صريحًا. مشرف البيئة يعمل ضمن كل بيئاته الحالية باستعلام مباشر، والمحدود المخول يشمل كل البيئات. صفحة الإدارة الجديدة تعرض الاسم والهوية والتواصل والمرحلة والبيئة وحالة الحساب فقط، دون أرصدة أو إحصاءات أو سجل نقاط أو مهام أو طلبات أو ملاحظات.

الإذن يسمح بإضافة طالب واحد، وتعديل حقول البيانات الأساسية، وتعطيل الحساب ناعمًا دون حذف `User` أو `Participant` أو التاريخ والأرصدة. لا يشمل استيرادًا جماعيًا أو إعادة تفعيل أو كلمة مرور أو دورًا أو امتيازات أدمن أو تعديل نقاط. الإضافة لا تقبل بيئة غير مسندة لمشرف البيئة؛ والمعرفات الخارجة عن نطاق التحرير أو التعطيل لا تُجلب. حسابات الطلاب ذات امتيازات الإدارة أو الأدوار غير الطلابية ليست أهداف إدارة.

تعطيل الحساب يتطلب تأكيدًا، ويوقف الجلسة الموجودة في الطلب التالي وفق backend الحالي. الاستعادة تبقى للعام والنظام. إعادة التفعيل لا تعيد منحًا مفوضة سُحبت. تبقى طريقة الأرصدة والتدقيق والمراجع كما هي.

## الاطلاع والإعداد

`SupervisorReportPermission` سجلOneToOne مستقل بعلمي `view_reports` و`prepare_reports` ومَنح `granted_by` وتاريخ `updated_at`. عدم وجود سجل يحافظ على السلوك القديم: تقارير الطلاب وPDF للبيئة/العام/النظام، ومركز التقارير للعام وحده، ولا تقارير للمحدود. وجود سجلFalse قرار منع حقيقي، لا رجوع إلى الوراثة. إعداد الملفات يتطلب الاطلاع مهما كانت البيانات المخزنة؛ النموذج يرفض طلب إعداد مع منع الاطلاع.

الاطلاع يسمح بعرض التقارير وتغيير الفلاتر وقراءة النتائج ضمن النطاق؛ الإعداد يعني إصدار ملفاتPDF وExcel من المنصة، لا إنشاء أرشيف تقارير دائم جديد. يمكن منح الاطلاع وحده مع إخفاء أزرار الملفات ورفض مسارات التصدير المباشرة. لا يمنع هذا الخيار نسخ البيانات المسموح بعرضها أو طباعتها بأدوات المتصفح.

عند المنع تُحجب صفحات تقرير الطلاب وملف الطالب وجدول البيانات وPDF ومركز التقارير وتصديره وتاريخ ملخص التصفير. تُمنع أيضًا بيانات رسوم لوحة العام نفسها وJSON وروابط المقارنة؛ لا يكفي إخفاء عناصر الرسم. تبقى الإدارة التشغيلية الأساسية وسجلات العمليات وصلاحيات المهام والمتجر والحضور بحسب أدوارها وأذوناتها، ولا يمنح إذن التقارير هذه العمليات. عند منع التقارير يستخدم المدير قائمة الطلاب الأساسية بدل الوصول إلى تقرير محجوب.

منح تقرير صريح لمشرف البيئة يتيح المركز ضمن بيئاته الحالية فقط؛ والمنح الصريح للمحدود يتيح التقارير في كل البيئات. النظام يحتفظ بالتقارير القديمة ولا يحصل على مركز التقارير الجديد. ملاحظات اللقاء الخاصة تبقى للبيئة/العام المخولين، ولا يقرأ المحدود أو النظام نصها حتى مع إعداد تقرير.

## السحب والأقفال والاستجابات

الحراس يقرؤون الدور والنشاط والسياسة من قاعدة البيانات، لا من كائن أو علاقة مخزنة في الذاكرة. الطالب ومَن لا يملك الإذن يُرفض قبل بيانات التقرير أو استيراد أداة التصدير. يتحقق تعديل الطلاب وتعطيلهم بعد قفل المستخدمين المرتب ثم صف المشارك فقط. المنح والسحب يقفلان المستخدمين قبل سجل الإذن؛ لذلك لا تعتمد الكتابات على صفحة قديمة أو إذن سُحب أثناء انتظارها.

العمليات ذرية، والتأكيد وقيمcheck boxes هيyes واحدة؛ التكرار لا يكرر السجل أو يغيّر التوقيت. تغير الدور أو تعطيل الحساب يسحب الأعلام المفوضة والمنح الإيجابية الصريحة للتقارير، ويحافظ على سجلات المنعFalse. لا تُنشأ سياسة منع جماعية للحسابات القديمة. كل استجابات التقرير المسموحة والمرفوضة والملفات والروابط المحولة خاصة `private, no-store`؛ والتقرير المحجوب لا يبني بيانات أو سياقًا خاصًا.

الهجرة0027 تضيف علم الطلاب ونموذج سياسة التقارير فقط: لا `RunPython`، ولا تحويل أدوار أو أرصدة أو ملء سياسات قديمة.

## المسارات والمراجع

- `participants:student_management`: قائمة الإدارة الأساسية.
- `participants:supervisor_student_reports`: صفحة سياسة الطلاب والتقارير للمشرف الهدف.
- `participants/student_management.py`: نطاقات الطلاب والإدارة الأساسية.
- `participants/supervisor_permissions.py` و`supervisor_permission_forms.py`: المنح والتأكيد.
- `participants/capabilities.py`: الأذونات الحديثة والوراثة والمنع والسحب.
- `participants/reporting.py`: نطاق التقارير والاستجابات الخاصة؛ ومنه خدمات المركز وملف الطالب.

راجع [الأدوار والصلاحيات](roles-and-permissions.md) و[مركز التقارير](report-center.md) و[إدارة الهوية](authentication.md).

## استقلال التشغيل وروابط الملفات

منع التقارير لا يمنع كشف التحضير أو تصحيح المهام أو المتجر أو دفتر العمليات
الممنوحين بالدور/الأعلام القائمة؛ يستخدمان نطاق تشغيل مستقلًا فيaccess.py،
بينما نطاقreporting.py لا يرد بيانات للممنوع. يمنع ذلك أن يكون خيار التقارير
مصدر صلاحية تشغيل أو أن يسحب تشغيلًا قائمًا. روابط ملف الطالب وجدول التقرير
في الكشوف لا تظهر عند المنع؛ يبقى الاسم والتحضير والبحث والحفظ دون تغيير.
تقرير ملف الطالب ليس بديلًا لقائمة الإدارة الأساسية: من يملك الطلاب فقط
يعمل في تلك القائمة دون الحصول على الإحصاء. المعلومات التشغيلية اللازمة
للوظائف القائمة ليست «إذن تقارير» ولا تُسحب معه تلقائيًا.
